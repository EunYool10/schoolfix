# SchoolFix AI — 학교 불편사항 신고 및 시설 안전 관리

학생이 학교별 교내 시설 문제를 신고하면, AI가 위험도를 채점하고, 누구나 처리 현황을 확인할 수 있는 **로그인 없는 공개형 웹 서비스**입니다.

"복도 타일이 들떠서 넘어질 뻔했다" 같은 제보가 종이나 구두로 흩어지지 않고, 접수번호와 위험도가 남는 기록으로 관리되는 것을 목표로 합니다.

---

## 무엇을 할 수 있나

로그인도 회원가입도 없습니다. 첫 접속에서 지원 학교를 고르면, 학교별 신고와 확인된 위치 카탈로그가 적용됩니다.

- **신고 등록** — 선택한 학교의 공식 확인 위치를 고르고, 공개되지 않은 건물·층·학과·학년·반·호실은 필요할 때 직접 입력합니다. 이름·학번·연락처는 **수집하지 않습니다.**
- **학교 지원** — 지원 학교는 학교 선택 화면에서 고릅니다. 학교 추가 신청은 웹 내부 신청함(운영진 메일함) 또는 `mailto:` 메일 초안으로 보낼 수 있고, 운영진이 메일함에서 승인하면 바로 지원 학교로 등록됩니다.
- **작성 도우미** — 학교급·장소에 맞춘 예시 89종(문제 종류별로 거르기)을 제공합니다. 예시를 고르면 제목·장소·분류·설명이 채워지고, 설명의 [ ] 빈칸만 실제 상황으로 바꾸면 됩니다. 빈칸이 남아 있으면 접수되지 않으며, 고르기 전 내용으로 되돌릴 수 있습니다.
- **사진 한 장으로 신고** — 문제가 보이게 사진을 찍거나 고르면 AI가 제목·장소·문제 종류·설명 초안을 채우고, 사진은 신고에 붙습니다. 장소·문제 종류는 학교 목록에 있는 값만 받고, 설명에는 "언제부터"·"불편한 점" 빈칸을 넣어 학생이 확인해야 접수되게 했습니다. 사진에 사람이 보이면 얼굴 자리를 모자이크하고, 학생이 **가리기** 도구로 더 가릴 수 있습니다(가린 사진만 올라감). 서버에 `OPENAI_API_KEY`가 없으면 이 기능은 보이지 않습니다. 사진 분석 요청은 저장하지 않습니다.
- **소음 재기** — 문제 종류로 "소음 문제"를 고르면 휴대폰 마이크로 10초 동안 소리 크기를 재서 평균·최고 dB를 신고에 붙입니다. 소리는 녹음하지 않고 숫자만 남깁니다. 휴대폰마다 마이크가 달라 화면과 운영진 화면 모두 "추정치"로 보여 줍니다.
- **AI 추가 질문** — 내용이 애매하면 바로 접수하지 않고, 가장 중요한 질문 **하나**를 되묻습니다. 답변을 합쳐 다시 판단하고, 충분해지면 그때 저장합니다.
- **내 신고 / 전체 신고** — 탭으로 구분해 조회합니다. 검색, 카테고리·위험도·처리 상태·기간 필터를 조합할 수 있습니다.
- **다른 기기에서 내 신고 불러오기** — 접수할 때 접수번호와 함께 **확인 코드**(예: `ABCDE-FGHJK`)를 한 번 보여 줍니다. 휴대폰을 바꾸거나 브라우저 데이터를 지워도 "내 신고" 탭에서 두 값을 넣으면 다시 연결되어 학교 답변과 만족도 응답을 이어서 할 수 있습니다.
- **처리 소식 알림** — "내 신고" 탭에서 알림을 켜면, 처리 상태가 바뀌거나 학교 답변이 달리거나 보류 신고가 공개될 때 휴대폰·PC로 알림이 옵니다(Web Push). 알림에는 접수번호와 바뀐 상태만 담고 신고 내용은 담지 않습니다.
- **추가 설명 덧붙이기** — 접수한 뒤에도 내 신고 상세에서 설명과 사진(최대 3장)을 덧붙일 수 있습니다(신고 하나에 10번까지). "아직 물이 새요, 이 사진을 보세요"처럼 학교 답변에 이어 대화하듯 쓰고, 신고한 나와 학교만 봅니다. 글과 사진은 신고와 같은 안전성 검사를 거칩니다.
- **위치별 신고 현황** — 어느 장소에서 문제가 가장 많이 발생하는지 실제 신고 데이터로 집계합니다. 위의 필터가 그대로 반영됩니다.
- **AI 요약** — 접수된 신고 전체에서 드러나는 문제 상황을 간결하게 정리합니다.
- **PDF 저장 / 인쇄** — 현재 필터가 적용된 목록을 보고서 형태로 내보냅니다.
- **간편 신고 작성** — 작성 진행 표시, 문제 종류 바로 선택, 자주 쓰는 예시, 사진 끌어놓기와 현재 탭 임시저장을 제공합니다. 초안에는 글 내용만 저장되며 사진과 AI 추가 질문 답변은 저장하지 않습니다.

학교별 데이터는 서버 측 [`schools.seed.json`](./schools.seed.json) 카탈로그에서 제공합니다. 학교 현황에 나온 학과 및 학년별 학급 수는 참고 정보로 저장하고, 실제 반 이름·건물명·층·호실은 공식 공개 자료에 없어 선택 목록으로 만들지 않고 신고자가 직접 적도록 했습니다. 기존 신고에는 기본 지원 학교 ID를 읽을 때 연결하며 신고번호와 내용을 초기화하거나 삭제하지 않습니다.

운영진 전용 화면에서 신고 현황을 확인하고 처리 상태·담당자·처리 메모를 관리할 수 있습니다. 상태와 위험도별 요약, 검색·필터, 위험도 우선 정렬을 제공하며 현재 조건에 맞는 신고 목록을 CSV로 내려받을 수 있습니다. 목록은 **30초마다 자동으로 갱신**되고, 새로 들어온 신고와 학생이 새로 덧붙인 설명에는 "새로 들어옴"·"새 추가 설명" 표시와 함께 브라우저 탭 제목에 건수가 붙습니다. 처리 내용을 입력하는 중에는 갱신을 잠시 건너뜁니다.

### 삭제 기록 · 되살리기 · 운영 기록 · 백업

- **삭제는 개인 계정으로, 사유와 함께** — 신고 삭제(사유 필수)·장난 신고 처리·검토 대기 신고 삭제는 운영진 화면에서 **개인 계정으로 로그인해야만** 할 수 있습니다. 누가 언제 왜 지웠는지 처리 이력과 운영 기록에 남습니다. 예전처럼 공개 화면에서 공용 관리자 비밀번호로 지우는 기능은 없앴습니다.
- **삭제된 신고 (휴지통)** — 관리자는 삭제된 신고를 보고 **되살리거나**, 개인정보 삭제 요청처럼 꼭 필요할 때 **영구 삭제**할 수 있습니다. 사진은 삭제 후 30일(`DELETED_PHOTO_RETENTION_DAYS`) 동안 비공개로 보관되어 그 안에 되살리면 함께 돌아오고, 기간이 지나면 저장소에서 지워집니다.
- **운영 기록** — 로그인, 계정 만들기·바꾸기·중지·삭제, 총괄 지정·넘기기, 신고 삭제·되살림·영구 삭제, 백업·되돌리기, 학교 등록, 알림 설정 변경을 누가 언제 했는지 최근 1,000건까지 남깁니다(관리자 이상 열람). 학생 정보와 실패한 로그인 시도는 넣지 않습니다.
- **자동 백업과 되돌리기** — 매일 한 번(한국 날짜 기준, 서버가 잠들어 있었으면 깨어날 때) 저장소 전체를 비공개 백업 보관소(Supabase Storage `schoolfix-backups`)에 저장하고 최근 30개를 남깁니다. 관리자는 "지금 백업"과 내려받기를, **총괄은 백업 시점으로 되돌리기**를 할 수 있습니다. 되돌리기 직전 상태는 자동으로 따로 백업되어 다시 되돌릴 수 있고, 계정·로그인·학생 알림 구독은 바뀌지 않습니다.
- **총괄 비상 복구** — 총괄이 비밀번호를 잊었거나 연락이 닿지 않으면 Render 환경변수 `OWNER_RESET_PASSWORD_HASH`(+ 새 총괄로 만들 계정이면 `OWNER_RESET_USERNAME`)를 넣고 재배포합니다. 서버가 시작할 때 한 번만 적용하고 운영 기록에 남깁니다. 적용된 뒤 로그인해서 비밀번호를 바꾸고 두 값을 지우세요.

### 운영진·교사 계정

- **개인 계정** — 관리자가 "계정 관리" 화면에서 사람마다 계정(관리자·운영진·교사)을 만듭니다. 처리 이력에 **누가 바꿨는지 이름**이 남고, 담당자가 바뀌면 그 계정만 끄면 됩니다. 계정을 끄거나 비밀번호를 바꾸면 열려 있던 로그인이 바로 끝납니다.
- **역할** — 총괄 > 관리자 > 운영진 > 교사.
  - **총괄**(1명): 모든 계정 위의 1인자. 관리자 계정을 만들고 바꾸는 일은 총괄만 하고, 총괄 계정은 다른 누구도(공용 비밀번호 관리자 포함) 바꾸거나 끄거나 지울 수 없습니다. 자리는 총괄 본인만 다른 사람에게 넘길 수 있고, 넘긴 사람은 관리자가 됩니다. 총괄이 아직 없으면 관리자가 "계정 관리"에서 한 사람을 **총괄로 지정**합니다.
  - **관리자**: 모든 기능 + 운영진·교사 계정 관리 + 삭제된 신고 되살리기·영구 삭제 + 운영 기록 + 백업. (총괄이 없을 때는 관리자 계정도 관리)
  - **운영진**: 모든 학교의 신고 처리·삭제·학교 신청·알림 설정. **교사**: 소속 학교 신고만 처리(삭제 불가).
  - 백업으로 되돌리기는 총괄만 할 수 있습니다.
- **공용 비밀번호도 그대로** — `STAFF_PASSWORD_HASH`(아이디 `admin` 또는 비움, 관리자 권한)와 학교별 `SCHOOL_TEACHER_PASSWORD_HASHES`는 계속 쓸 수 있습니다. 처음에는 공용 비밀번호로 들어가 개인 관리자 계정을 만드세요.
- **로그인 유지** — 로그인 세션의 해시를 저장소에 함께 저장해, 무료 플랜에서 서버가 잠들었다 깨거나 재배포돼도 8시간 동안 다시 로그인하지 않습니다.

### 학생 참여와 운영 기능

- **나도 겪었어요** — 같은 문제를 겪은 학생은 새로 신고하는 대신 기존 신고에 공감합니다. 기기마다 한 번만 세며, 운영진은 공감 많은 순으로 정렬할 수 있습니다.
- **처리 완료 후 만족도 확인** — 처리 완료된 내 신고에 "해결됐어요 / 아직 그대로예요"로 응답합니다. 미해결로 응답하면 신고가 다시 "확인 중"이 됩니다.
- **진짜 고쳐졌나요?** — 처리 완료되면 "나도 겪었어요"를 눌렀던 학생에게 알림이 가고(알림을 켠 기기), 그 학생들이 👍 고쳐졌어요 / 👎 아직 그대로예요를 누릅니다. 👎가 2명 이상이고 👍보다 많으면 신고가 자동으로 다시 "확인 중"이 되고, 처리 이력에 이유가 남습니다. 공감했던 기기만 누를 수 있고, 처리 완료 뒤에는 새로 공감할 수 없습니다(장난으로 다시 열지 못하게). 다시 완료되면 처음부터 새로 셉니다.
- **내가 바꾼 학교** — "내 신고" 탭 위에 이 기기에서 한 신고·공감·확인으로 고쳐진 곳을 학년도(3월 시작)별로 보여 주고, 학교 이름과 숫자, 고쳐진 곳 제목만 담은 카드 이미지로 저장할 수 있습니다. 서버에 묻지 않고 이 기기에 남은 기록으로 계산합니다.
- **학교의 답변** — 운영진·교사가 신고한 학생에게만 보이는 답변을 남깁니다. 공개 "처리 결과"(처리 메모)와는 별개입니다.
- **처리 기한** — 긴급 1일·높음 3일·중간 7일·낮음 14일(분석 전 7일). 기한을 넘긴 신고는 운영진 화면에 빨간색으로 표시하고 "기한 초과"로 필터·정렬할 수 있습니다.
- **처리 이력** — 상태·담당자·학생 답변 변경, 안전성 검토, 삭제·되살림, 학생 추가 설명, 만족도 응답을 누가(운영진/교사/신고자, 개인 계정이면 이름) 언제 했는지 기록합니다.
- **월별 통계와 보고서** — 월별 접수·완료율·평균 처리 시간·기한 초과 완료, 유형·위치·위험도별 접수, 최근 6개월 추이를 보여 주고 인쇄·PDF 보고서로 내보냅니다. 월 경계는 한국 시간 기준입니다.
- **학교 추가를 화면에서 처리** — 학교 신청 메일함에서 "승인하고 학교 등록"을 누르면 재배포 없이 학교 선택 화면에 바로 나타납니다. 위치는 기본 유형이 "확인 필요" 상태로 제공됩니다.
- **반복 신고자 걸러내기** — 학교는 학생 전체가 IP 하나를 쓰는 경우가 많아, 브라우저별 기기 토큰(서버에는 해시만 저장)으로 구분합니다. 10분 안에 3건 넘게, 하루 10건 넘게 보낸 기기의 신고와 운영진이 "장난 신고로 처리"한 기기의 신고(30일)는 **거부하지 않고 공개 전에 운영진 검토**를 거칩니다.
- **운영진 알림 (Discord 등)** — `NOTIFY_WEBHOOK_URL`로 Discord·Slack 등에 알립니다. 카카오톡·이메일은 Make·Zapier 같은 도구의 웹훅을 연결해 전달합니다.
  - 모든 신고(공개 보류 포함): 새 신고가 접수될 때마다 바로. **공개 보류 신고는 보류 사유·전체 내용·첨부 사진까지** 함께 보냅니다(사진 첨부는 Discord만). 보류 사진은 부적절할 수 있으니 운영진 전용 비공개 채널을 쓰세요.
  - 긴급 신고: 위험도가 기준(기본 "긴급") 이상인 신고. "모든 신고" 알림이 꺼져 있을 때와 접수 뒤 위험도 분석에서 늦게 긴급으로 판정됐을 때 보냄
  - 학교 신청 메일함: 새 학교 추가 신청이 들어오면 바로 (회신 이메일은 싣지 않음)
  - 월간 보고: 매달 1일 오전 9시 이후(한국 시간) 지난달 학교별 통계를 한 번. 서버가 잠들어 있었다면 깨어날 때 보냄
  - 운영진 화면 **"알림" 탭**에서 연결 상태 확인, 알림 종류 켜기/끄기, 테스트 알림, 원하는 달의 월간 보고 즉시 발송. "월별 통계" 탭에도 "디스코드로 보내기" 버튼이 있습니다.

### 위험도 분석

신고를 접수하면 서버가 AI에게 5개 요소를 각각 0~4점으로 채점하게 하고, **점수 계산과 등급 결정은 서버가** 합니다.

```
risk_score = (즉시성×30 + 사고가능성×30 + 피해정도×25 + 지속성×10 + 영향범위×5) / 4
             0~24 낮음 · 25~49 중간 · 50~74 높음 · 75~100 긴급
```

AI가 보낸 점수와 등급은 신뢰하지 않고 공식으로 다시 계산합니다. 덕분에 같은 신고를 여러 번 분석해도 결과가 흔들리지 않습니다. 즉각적인 안전 위험(전선 불꽃, 실제 화재, 구조물 낙하 임박 등)은 점수보다 우선해 긴급으로 올리되, "화재 대피 훈련" 같은 문맥은 구분합니다.

### AI 추가 질문

"학교가 별로예요" 처럼 담당자가 어디를 가서 무엇을 확인해야 할지 알 수 없는 신고는 그대로 저장해도 처리할 수 없습니다. 그래서 접수 전에 한 번 확인합니다.

```
신고 작성 → AI 확인 → 충분한가?
                       ├ 예   → 위험도 분석 → DB 저장
                       └ 아니오 → 질문 1개 → 답변 → 다시 확인 (최대 3회)
```

- **질문은 항상 하나**입니다. 여러 개가 오면 서버가 첫 질문만 남깁니다.
- 판단 기준은 "완벽한가"가 아니라 **"처리 가능한가"** 입니다. 장소와 문제만 알 수 있으면 날짜·시각·인원이 없어도 바로 접수됩니다.
- 대화 상태(최초 내용·질문·답변·직전 판단)는 서버 메모리 세션에 있고, **충분하다고 판단되기 전에는 DB에 저장하지 않습니다.**
- AI가 신고에 없는 사실을 만들어내면 서버가 걸러냅니다. 상세 위치는 학생 문장에 실제로 있는 표현일 때만 받아들이고, 학생이 쓰지 않은 숫자가 들어간 요약은 버립니다.

### 위치별 신고 현황

신고 폼은 선택 학교의 위치 유형 및 공식 위치 카탈로그를 사용합니다. 공식 목록에 없는 건물·층·교실·공간은 직접 입력할 수 있고, 직접 입력 값은 공식 위치로 승격되지 않습니다. 집계 시 학생이 적은 상세 정보를 함께 사용하며, 표기가 흔들려도 **확실할 때만** 같은 장소로 묶습니다.

```
"본관 3층 화장실" · "본관3층 화장실" · "3층 화장실"   → 본관 3층 화장실 (3건)
"본관 3층 화장실" · "별관 3층 화장실"                → 건물이 다르므로 분리
"3층 화장실" · "3층 남자화장실"                      → 같은 곳인지 알 수 없으므로 분리
```

건물 정보가 빠진 표기는 같은 층·같은 장소의 건물 지정 그룹이 **정확히 하나일 때만** 흡수합니다. 후보가 둘 이상이면 어느 쪽인지 알 수 없으므로 합치지 않습니다. 이 판정은 전부 문자열 규칙이라 **OpenAI를 호출하지 않으며**, 같은 데이터에 대해 항상 같은 결과가 나옵니다.

장소별로 총 건수, 가장 많은 카테고리, 높음 이상 위험도 건수, 최근 신고 날짜를 표시합니다. 모두 서버가 실제 DB에서 계산한 값이며, 해당하는 신고가 없으면 빈 그래프 대신 안내 문구를 보여줍니다.

### 내 신고는 어떻게 식별하나

로그인이 없으므로 신고 등록 시 서버가 추측 불가능한 토큰을 발급합니다. **브라우저에는 원본 토큰만, 서버 DB에는 SHA-256 해시만** 저장됩니다. 사용자 ID를 임의로 만들지 않습니다.

브라우저 저장소를 지우거나 다른 기기에서 접속하면 내 신고 목록은 비어 있습니다. 이때는 접수할 때 받은 **확인 코드**로 다시 연결합니다. 확인 코드도 서버에는 해시만 저장하고, 접수번호와 코드가 모두 맞으면 그 기기용 소유 토큰을 새로 발급합니다(신고마다 최근 10개 기기까지). 어느 쪽이 틀렸는지는 알려 주지 않고, 시도 횟수를 제한해 코드 대입을 막습니다. 확인 코드가 생기기 전에 접수한 신고는 이 방법으로 불러올 수 없습니다.

## 로컬에서 실행하기

**필요한 것:** Node.js 20 이상

```bash
npm install
npm run dev          # http://localhost:3000
```

`.env.local` 파일을 만들어 값을 채웁니다. (`.env.example` 참고)

```bash
OPENAI_API_KEY="sk-..."
STAFF_PASSWORD_HASH="$2b$12$..."
```

키가 없어도 **신고 등록·조회·검색·필터·PDF·인쇄는 그대로 동작합니다.** 키가 없을 때 달라지는 점은 다음과 같습니다.

- 위험도 분석과 AI 요약은 꺼집니다.
- AI 추가 질문 없이 바로 접수합니다.
- 부적절한 내용 검사는 욕설 필터만 적용합니다. 사진이 붙은 신고는 안전성 검사를 할 수 없으므로 공개 전에 운영진 검토로 보류됩니다.

평문 비밀번호는 코드·번들·DB·로그 어디에도 저장하지 않습니다.

## 보안

로그인이 없다는 것이 보안이 없다는 뜻은 아닙니다.

- **입력 검증** — 프론트엔드 검증을 신뢰하지 않고 서버가 최종 판단합니다. 허용된 위치·종류, 길이 제한. 사진은 신고당 6장, 장당 5MB까지이며 PNG·JPG·GIF·WEBP만 받고, 확장자가 아니라 파일 내용으로 형식을 확인합니다.
- **부적절한 내용 보류** — 신고 텍스트와 첨부 이미지를 서버에서 OpenAI Moderation으로 검사합니다. 검토가 필요한 신고는 공개 목록·상세·통계에서 숨기고 운영진 검토 대기열에 보관하며, 운영진이 승인하거나 삭제할 수 있습니다. 검사 장애 시 이미지 첨부 신고는 자동 공개하지 않고 보류합니다.
- **욕설 필터** — 규칙 기반. 금지어 글자 사이 구분자를 허용하는 정규식으로 `씨 발`·`씨.발` 같은 우회를 잡되, 문장 전체 공백을 제거하지 않아 `보지 못했어요` 같은 정상 문장을 오탐하지 않습니다.
- **Rate Limit** — 신고 등록 / AI 요약 / 확인 코드 불러오기 / 알림 구독 / 추가 설명에 각각 적용. 학교는 NAT 뒤에서 IP를 공유하므로 신고 등록 한도는 여유 있게 잡았습니다. 운영진·교사 로그인은 **틀린 비밀번호만** 세서(15분에 10번) 같은 학교 교사 여러 명이 로그인해도 막히지 않습니다.
- **계정·세션** — 개인 계정 비밀번호는 bcrypt 해시로만 저장하고, 없는 아이디로 로그인해도 같은 시간이 걸리게 해 아이디 존재 여부가 드러나지 않습니다. 로그인 쿠키는 HttpOnly·SameSite=Strict이며 서버에는 그 SHA-256 해시만 남깁니다. 켜진 관리자가 하나도 없게 되는 변경(마지막 관리자 끄기·삭제)은 막습니다. 총괄 계정은 서버가 어떤 요청으로도 바꾸거나 끄거나 지우지 못하게 막고, 총괄 자리는 지금 총괄의 세션에서만 넘길 수 있습니다.
- **삭제 책임** — 신고를 지우는 모든 일은 개인 계정으로만, 사유와 함께 합니다. 처리 이력과 운영 기록에 누가 했는지 남고, 관리자가 되살릴 수 있습니다. 예전의 공용 관리자 비밀번호 삭제 기능(`ADMIN_PASSWORD_HASH`)은 없앴습니다.
- **저장 충돌 방지** — 문서를 저장할 때 마지막으로 읽은 버전(`updated_at`)이 그대로일 때만 씁니다. 배포 중 서버 두 대가 함께 돌 때 서로의 변경을 덮어쓰지 않고, 충돌하면 최신 내용을 다시 읽어 같은 작업을 다시 적용합니다. 다른 서버의 변경은 30초마다 확인해 가져옵니다.
- **학생 알림** — 서버가 임의 주소로 요청을 보내지 않도록 브라우저 제조사의 공식 푸시 서비스 주소(FCM·Mozilla·Apple·WNS)만 구독으로 받습니다. 실제로 있는 신고의 소유 토큰만 구독에 묶습니다.
- **Prompt Injection 방어** — 신고 내용은 `<report>` 안의 데이터로 고정되며, 그 안의 지시문은 실행하지 않습니다.
- **XSS** — React 기본 escape에 의존하며 `dangerouslySetInnerHTML`을 쓰지 않습니다.
- **보안 헤더** — CSP, X-Frame-Options, Referrer-Policy, HSTS(운영).
- **오류 비노출** — 사용자에게는 일반 메시지만, 상세는 서버 로그로.

## 배포

`render.yaml`이 포함되어 있어 Render에서 **New → Blueprint**로 저장소를 연결하면 구성됩니다. 비밀 값은 커밋하지 않고 Render 대시보드 **Environment**에서 입력합니다.

- `OPENAI_API_KEY`
- `STAFF_PASSWORD_HASH`, `SCHOOL_TEACHER_PASSWORD_HASHES` (예전 `ADMIN_PASSWORD_HASH` 는 더 이상 쓰지 않으니 지워도 됩니다)
- `SUPABASE_URL`, `SUPABASE_SECRET_KEY` (데이터를 영구 보관할 때, 아래 참고)
- `NOTIFY_WEBHOOK_URL` (운영진 알림을 받을 때)
- `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` (학생 알림을 쓸 때)

`PUBLIC_BASE_URL`은 `render.yaml`에 `https://schoolfix.onrender.com`으로 들어 있습니다. Render가 배정한 실제 주소가 다르면 이 값도 바꿔야 알림 속 링크가 맞습니다. 운영진 로그인 비밀번호 해시는 다음 명령으로 생성합니다.

```bash
node -e "console.log(require('bcryptjs').hashSync('운영진비밀번호', 12))"
```

STAFF 비밀번호는 공용 관리자 계정(아이디 `admin` 또는 비움)의 비밀번호입니다. 배포 후 이 비밀번호로 로그인해 **운영진 화면 → 계정 관리**에서 사람마다 개인 계정을 만들고, 개인 관리자 계정이 생기면 `STAFF_PASSWORD_HASH`는 지워도 됩니다. 로그인 세션은 8시간 뒤 만료되며, 해시가 저장소에 남아 서버가 재시작돼도 유지됩니다.

학생 알림을 쓰려면 `npx web-push generate-vapid-keys`로 만든 키 두 개를 `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`에 넣습니다. 키가 없으면 "알림 켜기" 버튼이 나오지 않을 뿐 다른 기능은 그대로입니다. iPhone·iPad는 Safari에서 **홈 화면에 추가**한 앱에서만 알림을 받을 수 있습니다(iOS 16.4 이상).

교사 비밀번호는 학교별로 별도 발급합니다. `schools.seed.json`의 학교 `id`를 키로 하는 JSON 객체에 bcrypt 해시를 등록하세요. 예: `{"cem-h":"$2b$12$..."}`. Render 환경 변수 `SCHOOL_TEACHER_PASSWORD_HASHES`에 등록하기 전까지 해당 학교 교사 로그인은 비활성화됩니다. 교사는 소속 학교 신고의 상태·담당자·처리 메모만 관리하며, 운영진 검토 대기열과 학교 신청 메일함은 이용할 수 없습니다.

배포 후 `https://<주소>/api/health`가 `{"status":"ok"}`를 반환하면 정상입니다.

### 첫 접속 지연 줄이기 (무료 플랜)

Render 무료 플랜은 15분 동안 요청이 없으면 서버를 재우고, 다음 접속에 30~60초가 걸립니다. 그래서

- 서버가 한국 시간 7~21시(`KEEP_AWAKE_HOURS`)에는 10분마다 자기 주소를 불러 깨어 있습니다. Render 가 넣어 주는 `RENDER_EXTERNAL_URL`(또는 `PUBLIC_BASE_URL`)을 씁니다.
- GitHub Actions(`.github/workflows/wake-up.yml`)가 아침 6시 50분에 서버를 깨우고, 낮에는 14분마다 한 번 더 부릅니다. 주소가 다르면 저장소 **Settings → Secrets and variables → Actions → Variables** 에 `SCHOOLFIX_URL` 을 넣으세요.
- 밤에는 잠들게 둡니다. 무료 플랜 사용 시간은 **계정 전체에서 한 달 750시간**이라, 하루 14시간 깨어 있으면 한 달 약 440시간입니다. 같은 Render 계정에 다른 무료 서비스가 있으면 합쳐서 750시간을 넘지 않는지 Render 대시보드의 사용량을 확인하세요.
- 완전히 없애려면 유료 플랜(Starter)으로 올리면 됩니다. 그때는 `KEEP_AWAKE_HOURS=off` 로 꺼도 됩니다.

### 총괄 비상 복구

총괄이 비밀번호를 잊었거나 연락이 닿지 않으면, Render 를 관리하는 사람이 다음과 같이 합니다.

1. 새 비밀번호의 해시를 만듭니다: `node -e "console.log(require('bcryptjs').hashSync('새비밀번호', 12))"`
2. Render Environment 에 `OWNER_RESET_PASSWORD_HASH` 를 넣습니다. 다른 사람을 새 총괄로 세우려면 그 사람의 아이디를 `OWNER_RESET_USERNAME` 에 넣습니다(지금 총괄은 관리자가 됩니다).
3. 저장하면 재배포되면서 한 번 적용되고 운영 기록에 남습니다. 새 비밀번호로 로그인해 **내 비밀번호** 에서 다시 바꾼 뒤, 두 환경변수를 지우세요. 같은 값으로는 다시 적용되지 않습니다.

### Supabase로 신고 데이터 영구 보관하기

Render 배포 흐름은 그대로 유지하고, 신고 및 학교 추가 신청 데이터만 Supabase에 저장할 수 있습니다.

1. Supabase에서 프로젝트를 만들고, **SQL Editor**에서 [`supabase/schema.sql`](./supabase/schema.sql)을 실행합니다.
   - **이미 Supabase를 쓰고 있었다면** 업데이트할 때마다 이 파일을 한 번 더 실행하세요. 화면에서 등록한 학교, 검토 대상 기기, 알림 설정, 운영진 개인 계정, 로그인 세션, 학생 알림 구독, 운영 기록을 저장할 수 있도록 테이블 제약을 갱신합니다. 실행하지 않아도 서버는 시작되지만 해당 기능의 저장이 "저장하지 못했습니다" 오류로 실패합니다(로그인 세션은 메모리로만 유지됩니다).
2. Supabase 프로젝트의 **Project URL**과 서버 전용 Secret key(`sb_secret_...`)를 확인합니다. 이 키는 브라우저나 저장소에 절대 올리지 마세요. 구형 `service_role` JWT도 지원하지만 새 프로젝트에서는 Secret key를 권장합니다.
3. Render의 `schoolfix` 서비스 **Environment**에 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`를 추가하고 저장합니다. `SUPABASE_SERVICE_ROLE_KEY`를 쓸 경우에는 `SUPABASE_SECRET_KEY`와 동시에 설정하지 마세요.
4. Render가 재배포된 뒤 `/api/health` 응답의 `dataStore`가 `supabase`인지 확인합니다.
5. 신고 사진은 신고 기록과 따로 **비공개 Storage 버킷**(`report-photos`, `SUPABASE_PHOTO_BUCKET`으로 변경 가능)에 저장됩니다. 서버가 시작할 때 버킷이 없으면 Secret key로 직접 만들므로 따로 할 일은 없습니다. `/api/health`의 `photos`가 `{ "store": "supabase", "ready": true }`이면 정상입니다. 버킷을 공개로 바꾸지 마세요. 공개 보류 신고의 사진은 서버가 운영진에게만 보여 줍니다.

두 환경변수는 반드시 함께 설정해야 합니다. 둘 중 하나만 있거나 테이블 접근에 실패하면 서버는 시작되지 않아 로컬 JSON 저장소로 조용히 되돌아가지 않습니다. Supabase 문서가 없을 때만 해당 종류의 로컬 JSON을 초기 가져옵니다. 이미 존재하는 문서는 자동으로 덮어쓰지 않으며, 문서 내용이 예상한 배열 형식이 아니면 서버가 시작을 거부해 잘못된 데이터 덮어쓰기를 막습니다. 배포 환경에 기존 JSON 파일이 없거나 별도 백업이 있다면 연결 전에 Supabase SQL Editor의 `schoolfix_store`에 가져오거나 운영자에게 데이터 이관을 요청해야 합니다.

**영구 저장 강제 안전장치:** Supabase 환경변수 설정 후 Render에 `REQUIRE_SUPABASE_STORE=true`를 추가하세요. 이 값이 켜져 있으면 Supabase 연결 설정이 빠진 배포는 시작되지 않습니다. 설정 전에는 `/api/health`가 `dataStore: "local-json"` 및 `persistence.durable: false`와 경고를 반환하므로 영구 저장 여부를 확인할 수 있습니다. Supabase 연결이 정상이라면 `dataStore: "supabase"`, `persistence.durable: true`가 표시됩니다.

### 무료 플랜을 쓸 때

- 15분간 요청이 없으면 잠들고, 다음 접속에 30~60초가 걸립니다. 낮 시간에는 위 '첫 접속 지연 줄이기' 설정으로 깨어 있습니다.
- Supabase 환경변수를 설정하지 않으면 기존 JSON 파일 저장소를 쓰므로 재시작·재배포 시 데이터가 초기화될 수 있습니다.

데이터를 계속 보관하려면 위 안내에 따라 Supabase를 연결하세요. 유료 플랜이라면 Supabase 대신 영구 디스크를 붙여도 됩니다. Render 서비스에 디스크(예: 마운트 경로 `/var/data`)를 추가하고 환경 변수 `DATA_DIR`을 같은 경로로 설정하면 JSON 데이터와 사진이 그 디스크에 저장됩니다.

## 알려진 제한

- **운영진 화면은 30초마다 다시 받아옵니다.** 실시간 연결(WebSocket)이 아니므로 새 신고가 화면에 나타나기까지 최대 30초가 걸립니다. 바로 알아야 하는 신고는 웹훅 알림(`NOTIFY_WEBHOOK_URL`)을 함께 쓰세요.
- **Rate Limit이 인메모리**입니다. 인스턴스를 여러 개로 늘리면 Redis 같은 공유 저장소가 필요합니다.
- **욕설 필터는 모음 삽입 우회를 잡지 못합니다.** 모음을 구분자로 허용하면 정상 문장을 오탐하므로 의도적으로 제외했습니다.
- **AI 추가 질문 대화는 서버 메모리에 있습니다.** 서버가 재시작되면 작성 중이던 추가 질문 대화는 처음부터 다시 해야 합니다. (운영진·교사 로그인 세션은 저장소에 남아 유지됩니다.)
- **확인 코드가 없는 예전 신고**는 다른 기기에서 불러올 수 없습니다. 확인 코드는 이 기능이 생긴 뒤 접수한 신고부터 발급됩니다.
- **백업 되돌리기는 계정을 바꾸지 않습니다.** 백업에는 비밀번호 해시가 없어서 계정·로그인·학생 알림 구독은 되돌리지 않습니다. 사진은 백업 파일이 아니라 사진 저장소에 있으므로, 삭제 후 보관 기간(30일)이 지나 지워진 사진은 백업으로도 돌아오지 않습니다.
- **운영 기록은 이 기능이 생긴 뒤부터** 남습니다. 그 전에 지운 신고는 '삭제된 신고'에 보이지만 누가 지웠는지는 '기록 없음'으로 나옵니다.
- **서버를 여러 대로 늘리면** 저장 충돌은 막지만, 다른 서버의 변경이 화면에 반영되기까지 최대 30초가 걸립니다(배포 중 잠깐 두 대가 도는 상황을 위한 장치입니다).
- **학생 알림은 브라우저 지원에 따라 다릅니다.** iPhone·iPad는 홈 화면에 추가한 앱에서만, 일부 브라우저(카카오톡 인앱 브라우저 등)에서는 받을 수 없습니다.
- `data/` 폴더에는 신고 내용과 사진이 저장되며 git에 포함되지 않습니다.
