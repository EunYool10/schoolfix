# SchoolFix AI — 학교 불편사항 신고 및 시설 안전 관리

학생이 교내 시설 문제를 신고하면, AI가 위험도를 채점하고, 누구나 처리 현황을 확인할 수 있는 **로그인 없는 공개형 웹 서비스**입니다.

"복도 타일이 들떠서 넘어질 뻔했다" 같은 제보가 종이나 구두로 흩어지지 않고, 접수번호와 위험도가 남는 기록으로 관리되는 것을 목표로 합니다.

---

## 무엇을 할 수 있나

로그인도 회원가입도 없습니다. 접속한 사람은 누구나 아래를 모두 쓸 수 있습니다.

- **신고 등록** — 위치(10종)와 문제 종류(7종)를 고르고 내용을 작성합니다. 사진 첨부를 지원하며, 이름·학번·연락처는 **수집하지 않습니다.**
- **작성 도우미** — 상황별 예시 문구 10종을 제공해, 무엇을 어떻게 써야 할지 막막한 학생도 버튼 한 번으로 초안을 채웁니다.
- **내 신고 / 전체 신고** — 탭으로 구분해 조회합니다. 검색, 카테고리·위험도·처리 상태·기간 필터를 조합할 수 있습니다.
- **AI 요약** — 접수된 신고 전체에서 드러나는 문제 상황을 간결하게 정리합니다.
- **PDF 저장 / 인쇄** — 현재 필터가 적용된 목록을 보고서 형태로 내보냅니다.

관리자 대시보드는 없습니다. 권한이 필요한 기능은 **신고 삭제** 하나뿐입니다.

### 위험도 분석

신고를 접수하면 서버가 AI에게 5개 요소를 각각 0~4점으로 채점하게 하고, **점수 계산과 등급 결정은 서버가** 합니다.

```
risk_score = (즉시성×30 + 사고가능성×30 + 피해정도×25 + 지속성×10 + 영향범위×5) / 4
             0~24 낮음 · 25~49 중간 · 50~74 높음 · 75~100 긴급
```

AI가 보낸 점수와 등급은 신뢰하지 않고 공식으로 다시 계산합니다. 덕분에 같은 신고를 여러 번 분석해도 결과가 흔들리지 않습니다. 즉각적인 안전 위험(전선 불꽃, 실제 화재, 구조물 낙하 임박 등)은 점수보다 우선해 긴급으로 올리되, "화재 대피 훈련" 같은 문맥은 구분합니다.

### 내 신고는 어떻게 식별하나

로그인이 없으므로 신고 등록 시 서버가 추측 불가능한 토큰을 발급합니다. **브라우저에는 원본 토큰만, 서버 DB에는 SHA-256 해시만** 저장됩니다. 사용자 ID를 임의로 만들지 않습니다.

브라우저 저장소를 지우거나 다른 기기에서 접속하면 내 신고 목록은 비어 있습니다. 전체 신고에서는 계속 보입니다.

## 기술 구성

| 영역 | 사용 기술 |
|---|---|
| 프론트엔드 | React 19, TypeScript, Tailwind CSS 4, Vite 8 |
| 백엔드 | Express 4 (`server.ts`) |
| 저장소 | JSON 파일 (`data/reports_db.json`) |
| AI | OpenAI `gpt-5.6-terra` → `gpt-5.6-luna` 폴백, **서버에서만 호출** |
| 인증 | 없음 (삭제만 bcrypt 비밀번호 검증) |
| PDF / 인쇄 | 별도 라이브러리 없이 `@media print` + `window.print()` |

## 로컬에서 실행하기

**필요한 것:** Node.js 20 이상

```bash
npm install
npm run dev          # http://localhost:3000
```

`.env.local` 파일을 만들어 값을 채웁니다. (`.env.example` 참고)

```bash
OPENAI_API_KEY="sk-..."
ADMIN_PASSWORD_HASH="$2b$12$..."
```

키가 없어도 **신고 등록·조회·검색·필터·PDF·인쇄는 그대로 동작합니다.** 위험도 분석과 AI 요약만 비활성화됩니다.

### 환경 변수

| 변수 | 필수 | 설명 |
|---|---|---|
| `OPENAI_API_KEY` | AI 기능 사용 시 | 위험도 분석 + AI 요약 |
| `ADMIN_PASSWORD_HASH` | 삭제 기능 사용 시 | bcrypt 해시. 없으면 삭제가 503 |
| `DATA_DIR` | 선택 | JSON 저장 경로. 영구 디스크용 |
| `ALLOWED_ORIGINS` | 선택 | 교차 출처 허용 도메인 |
| `PORT` | 선택 | 기본 3000. 호스팅이 자동 주입 |

관리자 비밀번호 해시 생성:

```bash
node -e "console.log(require('bcryptjs').hashSync('원하는비밀번호', 12))"
```

평문 비밀번호는 코드·번들·DB·로그 어디에도 저장하지 않습니다.

### 명령어

```bash
npm run dev          # 개발 서버
npm run lint         # 타입 검사
npm run build        # 프로덕션 빌드
npm start            # 빌드 결과 실행
npm run test:risk    # 위험도 채점 검증 (OPENAI_API_KEY 있으면 실제 모델까지)
npm run test:filter  # 욕설 필터 검증
```

## API

로그인이 없으므로 대부분 공개입니다. 삭제만 2단계 인증을 거칩니다.

| 메서드 | 경로 | 권한 | 설명 |
|---|---|---|---|
| GET | `/api/health` | 공개 | 상태 확인 |
| GET | `/api/reports` | 공개 | 전체 신고 + 서버 계산 통계 |
| GET | `/api/reports/:id` | 공개 | 신고 상세 |
| POST | `/api/reports` | 공개 | 신고 등록 (소유 토큰 발급) |
| POST | `/api/reports/mine` | 공개 | 소유 토큰으로 내 신고 조회 |
| POST | `/api/ai/summary` | 공개 | AI 요약 (Rate Limit + 캐시) |
| POST | `/api/admin/verify-delete` | 비밀번호 | 삭제 토큰 발급 |
| DELETE | `/api/reports/:id` | 삭제 토큰 | Soft Delete |

응답에는 신고자 이름·이메일·IP·내부 식별자가 포함되지 않습니다. 서버가 화이트리스트 DTO로 변환해 내보냅니다.

## 보안

로그인이 없다는 것이 보안이 없다는 뜻은 아닙니다.

- **입력 검증** — 프론트엔드 검증을 신뢰하지 않고 서버가 최종 판단합니다. 허용된 위치·종류, 길이 제한, 첨부는 `data:image/*`만 허용.
- **욕설 필터** — 규칙 기반. 금지어 글자 사이 구분자를 허용하는 정규식으로 `씨 발`·`씨.발` 같은 우회를 잡되, 문장 전체 공백을 제거하지 않아 `보지 못했어요` 같은 정상 문장을 오탐하지 않습니다.
- **Rate Limit** — 신고 등록 / AI 요약 / 관리자 인증에 각각 적용. 학교는 NAT 뒤에서 IP를 공유하므로 신고 등록 한도는 여유 있게 잡았습니다.
- **Prompt Injection 방어** — 신고 내용은 `<report>` 안의 데이터로 고정되며, 그 안의 지시문은 실행하지 않습니다.
- **XSS** — React 기본 escape에 의존하며 `dangerouslySetInnerHTML`을 쓰지 않습니다.
- **보안 헤더** — CSP, X-Frame-Options, Referrer-Policy, HSTS(운영).
- **오류 비노출** — 사용자에게는 일반 메시지만, 상세는 서버 로그로.

## 배포

`render.yaml`이 포함되어 있어 Render에서 **New → Blueprint**로 저장소를 연결하면 구성됩니다. `OPENAI_API_KEY`와 `ADMIN_PASSWORD_HASH`는 커밋하지 않고 대시보드에서 입력합니다.

배포 후 `https://<주소>/api/health`가 `{"status":"ok"}`를 반환하면 정상입니다.

### 무료 플랜을 쓸 때

- 15분간 요청이 없으면 잠들고, 다음 접속에 30~60초가 걸립니다.
- 영구 디스크를 쓸 수 없어 **재시작·재배포 시 신고가 초기화됩니다.** 이때 `data.seed.json`의 예시 신고가 자동 복원되어 화면이 비지는 않습니다.

데이터를 계속 보관하려면 유료 플랜에서 영구 디스크를 붙이거나(`render.yaml` 주석 참고), JSON 파일 대신 외부 데이터베이스를 연결해야 합니다.

## 알려진 제한

- **처리 상태를 바꾸는 기능이 없습니다.** 관리자 대시보드를 두지 않기로 했기 때문에, 새로 접수된 신고는 `접수 대기`에 머뭅니다. 처리 상태 필터는 기존 데이터에서만 의미가 있습니다.
- **Rate Limit이 인메모리**입니다. 인스턴스를 여러 개로 늘리면 Redis 같은 공유 저장소가 필요합니다.
- **욕설 필터는 모음 삽입 우회를 잡지 못합니다.** 모음을 구분자로 허용하면 정상 문장을 오탐하므로 의도적으로 제외했습니다.
- `data/` 폴더에는 신고 내용이 저장되며 git에 포함되지 않습니다.
